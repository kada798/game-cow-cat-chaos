# 场景回归测试

## 凳子幕（第三幕）

`npm run test:stool` 验证跳上凳子和抬爪、直接点击脚、脚先移开后猫才趴下、完成前不能进入下一幕、三语切换不重播、键盘和重玩、切走与后台中断无迟到通关、转屏保持动作、图片解码失败重试。检查三语各六组视口中脚尖确实可点、目标至少 44 像素，下一幕进入毛线关。总故事为十三幕。

## 中英法专项

`npm run test:i18n` 检查三个语言文件的 184 个键与插值参数一致；三语各自完整通关十三幕；运行中换语言保持脚印、步骤、通关状态和原动画；链接、记忆偏好与浏览器语言优先级；存储被禁用仍可切换；三语在六组视口中的按钮与文字可达性。词条检查及运行画面检查覆盖中文泄漏，无障碍标签也参与检查。

`npm test` 首先运行凳子幕专项，再运行三语、十三幕和原场景专项。旧专项通过 `lang=zh` 固定语言，避免机器浏览器语言改变测试含义。

游戏可直接打开根目录的 `index.html`，不依赖这些测试工具。

在本目录执行：

```powershell
npm install
npx playwright install chromium
npm test
```

也可以分别执行 `npm run test:ambush`、`npm run test:yarn`、`npm run test:dad` 和 `npm run test:teddy`。`npm test` 按顺序执行十三幕集成测试与四个专项测试，任一个失败即返回非零退出码。

## 测试前提

这些是运行在本地 `file://` 页面的真实 Chromium 测试，不启动服务器、不模拟成功的游戏控制器。新的第二场景必须已接入 `index.html`：唯一 `.scene` 的 `data-scene="yarn"`，并提供 `.yarn-scene.is-ready`、`#featherToy`、`#yarnMess`、`#yarnControls` 等约定接口。运行文件尚未接入时，不应把测试失败当作已完成运行验证。

已有独立 browser-check 环境时，可复用依赖，避免在项目里重复安装：

```powershell
$check = 'C:\Users\86155\.codex\visualizations\2026\05\11\019e16e2-85c1-7e62-9fab-11ad6fb1c29a\browser-check'
$env:NODE_PATH = "$check\node_modules"
$env:PLAYWRIGHT_BROWSERS_PATH = "$check\browsers"
npm run test:yarn
npm test
```

## 十三幕流程新增覆盖

`npm run test:story` 验证十三幕顺序完成、原四幕衔接、错误反馈、上一幕、章节预览、重玩、结尾键盘摸头、从头开始、切走取消原控制器，以及六组视口下的初始画面与每一步操作可达性。原专项测试以章节ID或原预览链接进入，不再假设游戏从沙发埋伏开始。

## 覆盖范围

- `teddy.cjs`：检查前爪与白熊头部透明轮廓重叠、后爪落在床垫上、两个前爪反相交替而身体不平移、头部轻压缩。验证玩具响声、两人到位后才停爪、最终像素静止、无自动过场、静音重玩、快速连点、后台/离开取消、加载失败重试、键盘及减少动态效果；13 组屏幕（含反馈中的 486×668）均保存踩踏和围观停爪截图，前缀 `teddy-`。根据背景 cover 裁切后的真实墙地分界，验证两人的脚底锚点落在木地板上且位于床侧；竖屏女孩不能挡住爸爸脚底，停爪素材必须保持已确认的小乐造型。完整过场测试已改为第四幕成功后明确点击“看看结局”。

- `dad.cjs`：验证中文/英文名称、无倒计时轻拍循环、猫爪接触光头的坐标、爸爸摸头与装乖反应。用截图像素对比检查只露老鼠尾巴；验证完整露出后才吱叫，猫沿靠背移动并跳下追逐，成功后等待明确下一幕。覆盖静音、快速重复点击、重玩只记录一次场景完成、追逐中转屏、四个阶段进入后台、离开无迟到事件、图片解码失败重试、键盘及减少动态效果。截图前缀为 `dad-`，适配覆盖与前两幕相同的 12 组视口。

- 毛线专项：对比实际屏幕尺寸验证球直径为猫头宽的 0.8 倍；边缘玩具只露一角，触摸区仍至少 44 像素，且远离球。验证猫爪后收时球平移、旋转和连接线一起变化，玩具展开完成后才响铃，静音重玩不响铃。

- `ambush.cjs`：检查足球可见直径为猫头宽的 2/3，像素对比确认手边只露球的一角，旧袜子不再触发。验证足球落稳后才有扑出状态、落点靠近脚边、成功后球留在地面、重玩重新掉球，以及重复点击、静音、掉落中后台中断、键盘和减少动态效果。衔接为埋伏完成 → 明确点击下一幕 → 毛线场景 → 点击羽毛玩具 → 等待救援成功 → 明确点击下一幕 → 爸爸、玩具熊及结尾。
- `yarn.cjs`：独立测试按章节ID定位进入毛线场景，断言图片就绪、`loading → playing` 和初始猫姿态。点击毛线是错误尝试，必须经过 `guarded → playing`，不触发救援或完成事件。
- 正确救援：检查实际 DOM 状态、`attracting → following → rescuing → rescued` 事件顺序、`play/alert/walk/pounce` 猫姿态，以及乱线保留、淡出与整理后毛线显示。快速连点只能启动一轮；成功状态保持至明确点击下一幕。
- 重玩：成功后恢复 `playing`、隐藏下一幕、还原乱线；再次救援产生递增的轮次，但同一次进入只产生一次 `scene_complete`，结果为 `yarn_rescued`。重新进入场景后才允许新增一次完成。
- 生命周期：移动中横竖屏切换不重置流程；在吸引、跟随、救援阶段分别模拟进入后台，未完成流程复位且不会延迟完成。离开场景后没有仍在运行的场景动画或迟到事件。
- 错误恢复：通过测试专用的原生图片 `decode()` 闸门暂停并使该场景图片解码失败，验证加载时禁用重玩、错误时可重试；恢复原生解码后重新加载并正常救援。闸门不修改游戏控制器或素材。
- 无障碍：按钮有可访问名称，原生键盘 Enter/Space 可完成错误尝试、救援、重玩和下一幕；减少动态效果设置下保留完整状态顺序。
- 埋伏与毛线均覆盖 12 组视口：320×568、390×844、430×932、568×320、870×612、768×1024、1024×768、820×1180、1191×668、1440×900、1920×1080、2560×1440。检查全屏填充、无页面溢出、图片加载、HUD 文字、控制按钮及道具按钮实际 `.hit-area` 至少 44 屏幕像素，触摸中心未被其它元素挡住。所有页面均监听 `pageerror`。

后台状态沿用埋伏测试的方式：临时覆盖 `document.hidden` 并发送 `visibilitychange`，随后恢复原生属性。这不等于操作系统真实挂起测试。

## 输出

第三幕新增检查：以电视可见轮廓和爸爸的可见轮廓检查观看间距，并验证侧向素材；读取猫爪和沙发透明像素，避免站立/装乖时悬浮；下调靠背位置后，拍头仍接触光头，扑跃仍落在原地。移动中切换横屏不会改变已发现玩具的固定起点。

截图默认生成在 `results/`。埋伏截图名保持不变；毛线截图始终以 `yarn-` 开头，包括各组视口、收爪拉线、玩具展开、救援前后、移动中及失败截图，不覆盖埋伏结果。可用 `AMBUSH_SCREENSHOTS`、`YARN_SCREENSHOTS` 分别指定输出目录。失败时会输出测试名、毛线事件记录和页面错误，方便区分状态、加载和布局问题。

通过这些测试不代表已在真实 iPhone、iPad 或系统后台挂起场景上实机验收。
